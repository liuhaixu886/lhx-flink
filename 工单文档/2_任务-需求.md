# 任务-需求

## 一、任务目标

建设一套实时数仓链路，并基于 ADS 指标完成实时可视化看板。系统需要支持业务数据和日志数据实时接入、基础清洗、维度入库、事实分流、窗口汇总、ADS 指标查询和页面展示。

## 二、总体需求

- 数据采集需要具备实时性。
- 数据分层需要符合 ODS、DIM、DWD、DWS、ADS 职责边界。
- ODS 层只做接入和基础格式保护。
- DIM 层负责维度数据配置化写入 HBase。
- DWD 层负责日志分流、业务事实分流和基础脏数据处理。
- DWS 层负责面向主题的 30 秒窗口汇总。
- ADS 层负责面向看板的指标视图。
- 看板层只读取 ADS，不直接访问明细层。

## 三、数据源需求

### 业务数据源

- 来源：MySQL `gmall` 数据库。
- 采集方式：Flink CDC 读取 MySQL Binlog。
- 输出主题：Kafka `topic_db`。
- 数据格式：Debezium JSON。
- 金额字段要求：MySQL Decimal 需要以字符串方式输出，避免 Base64 编码问题。

### 日志数据源

- 来源：Kafka `topic_log`。
- 数据格式：JSON 日志。
- 输出主题：Kafka `ods_log`。
- 要求：非法 JSON 或空字符串写入 `dirty_data`。

## 四、ODS 层需求

### 业务 ODS

- 从 `topic_db` 读取业务变更数据。
- 打印原始数据，方便观察采集入口。
- 校验是否为合法 JSON。
- 合法数据写入 `ods_db`。
- 非法数据写入 `dirty_data`。
- 不做业务字段清洗，不拆表。

### 日志 ODS

- 从 `topic_log` 读取日志数据。
- 打印原始数据，方便观察采集入口。
- 校验是否为合法 JSON。
- 合法数据写入 `ods_log`。
- 非法数据写入 `dirty_data`。
- 不做日志业务语义处理。

## 五、DIM 层需求

- 从 Kafka `ods_db` 读取业务变更数据。
- 使用 Flink CDC 读取 MySQL 配置表 `realtime_config.table_process_dim`。
- 配置表用于判断哪些业务表属于维表。
- 维表数据写入 HBase `gmall_dim` 命名空间。
- HBase 表不存在时自动创建。
- 支持配置字段：
  - `source_table`
  - `sink_table`
  - `sink_family`
  - `sink_row_key`
  - `sink_columns`
  - `sink_type`
- `sink_columns` 控制写入 HBase 的字段范围。
- rowkey 字段只作为 HBase 行键，不重复写入列族。
- 配置删除后，对应来源表停止写入 DIM。

## 六、DWD 层需求

### 日志 DWD

- 消费 `ods_log`。
- 非法 JSON、缺少 `common`、缺少 `ts`、缺少 `common.mid` 的数据写入 `dirty_data`。
- 同时缺少 `page` 和 `start` 的日志写入 `dirty_data`。
- 合法日志分流到：
  - `dwd_traffic_page_log`
  - `dwd_traffic_start_log`
  - `dwd_traffic_display_log`
  - `dwd_traffic_action_log`
  - `dwd_traffic_error_log`
- 曝光、动作、错误明细需要补充 `common`、`page`、`ts` 字段。

### 业务 DWD

- 消费 `ods_db`。
- 解析 Debezium JSON。
- 非法 JSON、缺少 `source.table`、缺少 `op` 的数据写入 `dirty_data`。
- `c/r/u` 事件缺少 `after` 的数据写入 `dirty_data`。
- 缺少主键 `id` 的事实数据写入 `dirty_data`。
- 删除事件第一版忽略。
- 维表数据不进入 DWD，交给 DIM 处理。
- 事实表分流主题包括：
  - `dwd_trade_order_info`
  - `dwd_trade_order_detail`
  - `dwd_trade_order_detail_activity`
  - `dwd_trade_order_detail_coupon`
  - `dwd_trade_payment_info`
  - `dwd_trade_order_refund_info`
  - `dwd_trade_refund_payment`
  - `dwd_trade_order_status_log`
  - `dwd_tool_coupon_use`
  - `dwd_interaction_favor_info`
  - `dwd_interaction_comment_info`

### 订单明细事实宽流

- 消费订单主表、订单明细、活动明细、优惠券明细 DWD 主题。
- 使用 Flink keyed state 做状态关联。
- 输出 `dwd_trade_order_detail_fact`。
- 状态 TTL 为 30 分钟。
- 输出字段包含订单明细、用户、省份、SKU、金额、活动、优惠券等信息。
- 异常数据写入 `dirty_data`。

## 七、DWS 层需求

### SKU 下单窗口汇总

- 输入：`dwd_trade_order_detail_fact`。
- 窗口：30 秒滚动窗口。
- 维度：`sku_id`。
- 指标：
  - `order_amount`
  - `order_count`
  - `sku_num`
- 输出 Doris 表：`dws_trade_sku_order_window`。
- 业务看板演示要求使用处理时间入窗，保证造数后看板实时变化。

### 省份下单窗口汇总

- 输入：`dwd_trade_order_detail_fact`。
- 窗口：30 秒滚动窗口。
- 维度：`province_id`。
- 指标：
  - `order_amount`
  - `order_count`
  - `sku_num`
- 输出 Doris 表：`dws_trade_province_order_window`。
- 业务看板演示要求使用处理时间入窗。

### 流量页面访问窗口汇总

- 输入：`dwd_traffic_page_log`。
- 窗口：30 秒滚动窗口。
- 指标：
  - `pv_ct`
  - `uv_ct`
  - `sv_ct`
- 输出 Doris 表：`dws_traffic_page_view_window`。
- 使用日志 `ts` 作为事件时间。

## 八、ADS 层需求

ADS 只基于 Doris DWS 表创建视图，不直接访问 Kafka 或 Flink 状态。

### 交易 ADS

- `ads_trade_stats_today`：交易总览。
- `ads_trade_sku_order_topn_today`：SKU GMV TopN。
- `ads_trade_trend_30s`：30 秒交易趋势。
- `ads_trade_hour_stats_today`：小时交易趋势。

### 省份 ADS

- `ads_trade_province_order_today`：省份交易汇总。
- `ads_trade_province_order_topn_today`：省份 GMV TopN。

### 流量 ADS

- `ads_traffic_stats_today`：流量总览。
- `ads_traffic_page_view_trend_30s`：30 秒流量趋势。
- `ads_traffic_hour_stats_today`：小时流量趋势。

### 日期要求

开发环境使用 DWS 表中的 `MAX(cur_date)` 作为最新统计日期，避免模拟业务时间和 Doris 当前日期不一致导致 ADS 查不到数据。

## 九、看板需求

### 看板刷新

- 看板只访问后端接口。
- 后端只查询 Doris ADS。
- 前端每 5 秒轮询一次。
- 指标粒度为 30 秒窗口。
- 接口异常时前端保留上一次正常数据，并显示连接异常。

### 看板展示

- 顶部 KPI：
  - GMV
  - 下单次数
  - 下单件数
  - 下单 SKU 数
  - PV
  - UV
  - SV
- 图表：
  - 交易 30 秒趋势
  - SKU GMV Top10
  - 省份 GMV Top10
  - 流量 30 秒趋势
  - 小时交易趋势
  - 小时流量趋势
- 页面状态：
  - 自动刷新状态
  - 最近请求时间
  - 数据日期
  - ADS 最新窗口时间

## 十、非功能需求

- 作业需要开启 checkpoint。
- Kafka 读写统一使用 UTF-8。
- 关键代码需要中文注释。
- 脏数据统一写入 `dirty_data`。
- Doris 写入使用 TSV/CSV 格式，避免 Doris Connector 1.0.3 的 String JSON 批量格式问题。
- 看板接口不允许前端传入任意 SQL。
- TopN 查询参数 `limit` 最大为 50，默认 10。

## 十一、验收标准

- `mvn clean compile` 通过。
- `mvn package -DskipTests` 通过。
- ODS 可以接收业务和日志数据。
- DIM 可以写入 HBase。
- DWD 可以完成日志和业务事实分流。
- DWS 可以写入 Doris。
- ADS 视图可以查出指标。
- 看板可以正常打开。
- 日志造数后，流量趋势图变化。
- 业务造数后，GMV、SKU TopN、省份 TopN 和交易趋势变化。
