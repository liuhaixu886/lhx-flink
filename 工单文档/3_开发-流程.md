# 开发-流程

## 一、开发准备

### 1. 项目环境

- JDK：Java 8
- 构建工具：Maven
- 实时计算：Flink 1.13.1
- Scala 二进制版本：2.12
- CDC：Flink CDC 2.1.1
- 消息队列：Kafka
- 维度存储：HBase 2.1.0
- 指标存储：Doris
- 后端服务：Spring Boot
- 前端看板：Vue3 + ECharts

### 2. Maven 依赖补充

先补齐 ODS、DIM、DWD、DWS 所需依赖：

- Flink 基础依赖
- Flink Kafka Connector
- Flink CDC MySQL Connector
- Fastjson
- HBase Client
- Doris Flink Connector
- SLF4J + Log4j
- Maven Compiler Plugin
- Maven Shade Plugin

开发过程中遇到 Doris Connector 依赖冲突，需要显式补充：

- `httpclient 4.5.13`
- `httpcore 4.4.13`

原因是 Doris Connector 依赖较新的 HttpClient API，如果被 Hadoop/HBase 传递进来的旧版 HttpClient 覆盖，会出现 `NoSuchMethodError`。

## 二、ODS 层开发流程

### 1. MySQL CDC 采集业务数据

开发 `ods_db_mysql_cdc_kafka` 作业：

- 使用 Flink CDC 读取 MySQL `gmall` 数据库。
- 输出 Debezium JSON 到 Kafka `topic_db`。
- 开启 checkpoint。
- 配置 Kafka Producer。

关键配置：

```java
debeziumProperties.setProperty("decimal.handling.mode", "string");
```

该配置用于解决 MySQL Decimal 字段被编码成 Base64 字符串的问题，保证金额字段后续可以正常聚合。

### 2. ODS 业务数据落主题

开发 `ods_db_sink` 作业：

- 消费 `topic_db`。
- 打印原始数据。
- 使用 Fastjson 做 JSON 合法性校验。
- 合法数据写入 `ods_db`。
- 非法数据或空字符串写入 `dirty_data`。

### 3. ODS 日志数据落主题

开发 `ods_log_sink` 作业：

- 消费 `topic_log`。
- 打印原始数据。
- 校验 JSON 格式。
- 合法数据写入 `ods_log`。
- 非法数据写入 `dirty_data`。

### 4. ODS 层边界确认

ODS 层只做基础格式保护，不做业务清洗、不拆表、不做字段建模。业务清洗和事实分流放到 DWD 层处理。

## 三、DIM 层开发流程

### 1. 配置表设计

在 MySQL 中创建配置库和配置表：

```sql
CREATE DATABASE IF NOT EXISTS realtime_config;

CREATE TABLE realtime_config.table_process_dim (
  source_table varchar(200) NOT NULL,
  sink_table varchar(200) NOT NULL,
  sink_family varchar(200) NOT NULL DEFAULT 'info',
  sink_row_key varchar(200) NOT NULL DEFAULT 'id',
  sink_columns varchar(1000) DEFAULT NULL,
  sink_type varchar(20) NOT NULL DEFAULT 'dim',
  PRIMARY KEY (source_table)
);
```

### 2. 配置化维度分流

开发 `dim_db_sink` 作业：

- 主流消费 Kafka `ods_db`。
- 配置流使用 Flink CDC 监听 `realtime_config.table_process_dim`。
- 将配置流广播到主流。
- 根据 `source.table` 判断数据是否属于维表。
- 命中配置的数据写入 HBase。
- 未命中配置的数据忽略，留给 DWD 处理事实数据。

### 3. HBase 写入规则

- namespace 固定为 `gmall_dim`。
- 表名取配置表 `sink_table`。
- 列族取 `sink_family`，默认 `info`。
- rowkey 取 `sink_row_key` 指定字段。
- `sink_columns` 控制写入字段。
- rowkey 字段不重复写入列族。
- 空值字段不写入 HBase。
- HBase 表不存在时自动创建。

### 4. DIM 验证

验证步骤：

```bash
hbase shell
list_namespace_tables 'gmall_dim'
scan 'gmall_dim:dim_base_province', {LIMIT => 5}
```

确认 HBase 表已创建，并且维表字段能够写入。

## 四、DWD 层开发流程

### 1. 日志 DWD 分流

开发 `dwd_log_split` 作业：

- 消费 `ods_log`。
- 校验 JSON、`common`、`ts`、`common.mid`。
- 页面日志写入 `dwd_traffic_page_log`。
- 启动日志写入 `dwd_traffic_start_log`。
- 曝光数组拆分写入 `dwd_traffic_display_log`。
- 动作数组拆分写入 `dwd_traffic_action_log`。
- 错误日志写入 `dwd_traffic_error_log`。
- 非法数据写入 `dirty_data`。

### 2. 业务 DWD 分流

开发 `dwd_db_split` 作业：

- 消费 `ods_db`。
- 解析 Debezium JSON。
- 提取 `source.table`、`op`、`after`。
- 维表数据不进入 DWD。
- 事实表按表名写入不同 Kafka 主题。
- 删除事件第一版忽略。
- 非法数据写入 `dirty_data`。

### 3. 订单明细事实宽流

开发 `dwd_trade_order_detail_fact` 作业：

- 消费：
  - `dwd_trade_order_detail`
  - `dwd_trade_order_info`
  - `dwd_trade_order_detail_activity`
  - `dwd_trade_order_detail_coupon`
- 使用 keyed state 关联订单明细和订单主表。
- 活动、优惠券按 `order_detail_id` 补充到明细事实。
- 状态 TTL 设置为 30 分钟。
- 输出 `dwd_trade_order_detail_fact`。

### 4. DWD 验证

使用 Kafka 消费命令验证主题是否有数据：

```bash
kafka-console-consumer.sh --bootstrap-server node101:9092 --topic dwd_trade_order_detail --from-beginning
kafka-console-consumer.sh --bootstrap-server node101:9092 --topic dwd_trade_order_info --from-beginning
kafka-console-consumer.sh --bootstrap-server node101:9092 --topic dwd_trade_order_detail_fact --from-beginning
kafka-console-consumer.sh --bootstrap-server node101:9092 --topic dwd_traffic_page_log --from-beginning
```

## 五、DWS 层开发流程

### 1. SKU 下单窗口汇总

开发 `dws_trade_sku_order_window` 作业：

- 消费 `dwd_trade_order_detail_fact`。
- 按 `sku_id` 分组。
- 30 秒滚动窗口。
- 统计：
  - 下单金额 `order_amount`
  - 下单次数 `order_count`
  - 下单件数 `sku_num`
- 写入 Doris `dws_trade_sku_order_window`。

### 2. 省份下单窗口汇总

开发 `dws_trade_province_order_window` 作业：

- 消费 `dwd_trade_order_detail_fact`。
- 按 `province_id` 分组。
- 30 秒滚动窗口。
- 统计：
  - 省份 GMV
  - 省份下单次数
  - 省份下单件数
- 写入 Doris `dws_trade_province_order_window`。

### 3. 流量页面访问窗口汇总

开发 `dws_traffic_page_view_window` 作业：

- 消费 `dwd_traffic_page_log`。
- 30 秒滚动窗口。
- 统计：
  - PV
  - UV
  - SV
- 写入 Doris `dws_traffic_page_view_window`。

### 4. Doris 写入格式调整

开发中发现 Doris Connector 1.0.3 使用 DataStream String Sink 写 JSON 时，批量数据可能被转成 List 字符串，导致 Doris Stream Load 过滤数据。

解决方式：

- Stream Load 使用 `format=csv`。
- 使用制表符作为列分隔符。
- 显式配置 `columns`。
- 输出 TSV 字符串写入 Doris。

### 5. 业务看板实时性调整

交易 DWS 最初使用订单 `create_time` 做事件时间。由于 GMall 造数的业务时间是模拟时间，后续新造数据可能落入历史窗口，导致交易看板不动。

调整方式：

- 交易 SKU DWS 和省份 DWS 使用处理时间入窗。
- 保证业务数据一进入 DWS，就能推动当前 30 秒窗口。
- 流量 DWS 继续使用日志 `ts` 作为事件时间。

### 4. ADS 日期口径调整

开发环境中，模拟业务时间可能和 Doris 机器当前日期不一致。如果 ADS 使用 `CURRENT_DATE()` 过滤，可能出现 DWS 有数据但 ADS 查不到。

解决方式：

```sql
WHERE cur_date = (
  SELECT MAX(cur_date)
  FROM gmall_realtime.dws_xxx
)
```

这样 ADS 始终查询 DWS 最新统计日期。

## 九、问题与解决经验

### 1. Flink CDC 缺少 TableException

问题：

```text
NoClassDefFoundError: org/apache/flink/table/api/TableException
```

解决：

- 补充 `flink-table-common` 依赖。

### 2. Kafka 客户端版本不兼容

问题：

```text
NoClassDefFoundError: org/apache/kafka/common/utils/ThreadUtils
```

解决：

- 显式指定 `kafka-clients 2.7.0`。

### 3. 金额字段变成乱码字符串

问题：

- MySQL Decimal 字段进入 Kafka 后出现类似 `CSoY`、`AA==` 的值。

解决：

- Flink CDC 增加 `decimal.handling.mode=string`。

### 4. Doris Stream Load 数据过滤

问题：

```text
[DATA_QUALITY_ERROR]too many filtered rows
```

解决：

- 不使用 String JSON 批量写入。
- 改用 TSV 格式。
- 显式配置 Doris `columns`。

### 5. ADS 查不到数据

问题：

- DWS 表有数据，ADS 视图查不到。

原因：

- ADS 使用 `CURRENT_DATE()`，但模拟数据日期和当前日期不一致。

解决：

- 改成查询 DWS 最新 `MAX(cur_date)`。

### 6. 业务看板不动

问题：

- 业务链路都在跑，但交易看板不刷新。

原因：

- 交易 DWS 使用业务 `create_time` 做事件时间，造数时间不推进。

解决：

- 交易 DWS 改成处理时间入窗。
- 流量 DWS 仍使用日志事件时间。
